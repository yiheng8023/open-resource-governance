## Project questions

Use public GitHub issues for public-safe questions about:

- repository roles and relationships;
- public/private boundaries;
- documentation gaps;
- resource-lane suggestions;
- validation or launch-gate clarification;
- contribution flow.

For support or sponsorship interest, see
[`support-and-sponsorship.md`](support-and-sponsorship.md). Use private contact
for funding conversations that include billing, identity, or non-public
coordination details.

Do not post private configuration, memory, private bookmarks, credentials,
tokens, cookies, OAuth material, local paths, account state, browser/session
data, or personal preference data in public issues.

## Security or private-data concerns

Use GitHub security advisories when available. If advisories are unavailable,
use an owner-controlled private contact path. Do not post sensitive material in
public issues, pull requests, discussions, screenshots, logs, or examples.

See [`../SECURITY.md`](../SECURITY.md) for the reporting scope and safe report
format.

## Cross-linking guidance

It is useful, but not required, to add a short link back to the project from
each public social profile that supports profile links or pinned posts.

Recommended link target:

```text
https://github.com/yiheng8023/open-resource-governance
```

Recommended profile wording:

```text
Building YIYUAN Meridian: public core, private overlays, release gates,
verifiable automation.
```

For platforms with limited profile space, prefer the GitHub repository link over
listing every social account. Avoid creating a dense link farm before there is a
real audience or a dedicated project landing page.

Avoid adding:

- private phone numbers;
- private email addresses not intended for public project use;
- personal WeChat IDs or QR codes unless the owner explicitly wants them public;
- accounts that are not owner-controlled;
- accounts that mix private life, sensitive work, or unrelated identity
  boundaries.

## Update rule

Contact and social links are owner-controlled public identity surfaces. Add,
remove, or change them through a reviewed pull request. Do not infer or scrape
contact information from other websites.
