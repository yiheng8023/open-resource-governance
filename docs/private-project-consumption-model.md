# Private Project Consumption Model

Public governance repositories can help private or core projects, but they must
not expose, define, or mutate those projects.

This model keeps the public system useful without turning a private project
into a public topology obligation.

## Boundary

Public repositories may provide:

- public-safe resource records;
- bookmark projections;
- candidate summaries;
- taxonomy and topology ideas;
- Skills governance evidence;
- templates, checklists, and validation patterns;
- generated reports that contain no private project state.

Private or core projects own:

- their real stage and roadmap;
- internal architecture and product body;
- private source truth;
- project-specific graph truth;
- adoption decisions;
- final standards and release authority.

## Allowed flow

```text
public-safe resource or governance output
-> neutral candidate evidence
-> private/project-specific review gate
-> optional absorption by the private project
```

The public side may prepare evidence. It must not decide final adoption for a
private/core project.

## Human intervention gates

Human review is required before:

- exposing a private project name, stage, roadmap, internal architecture, or
  freeze state;
- turning public evidence into a private project standard;
- writing into a private project repository;
- changing a private project's graph, release baseline, or governed truth;
- promoting a candidate lane into a maintained system.

Automation can collect, classify, summarize, generate, and verify public-safe
outputs. It should stop at absorption, exposure, or mutation boundaries.

## No hard-coded private consumer

This public ecosystem should not be framed as serving one named private
project. A private project may be an important consumer in a private context,
but the public model should remain reusable for many possible consumers.

That keeps the system:

- neutral;
- safer to publish;
- easier for other users to adapt;
- less dependent on one hidden project;
- able to evolve as new terminal lanes appear.

## Practical test

A real consumption test should answer:

1. Did a public lane produce a useful public-safe artifact?
2. Did the artifact clearly state what it proves and what it does not prove?
3. Did the process stop before private exposure or mutation?
4. Could a human reviewer accept, reject, or redirect the candidate?
5. After the human decision, could the chain resume and close the loop?

If all five are true, the public-to-private consumption model is working.
